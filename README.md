# DVSystem: NetSapiens Web Responder

A PHP server-side IVR for the Dee Voch Phone API. This incomplete version handles caller lookup, SMS-code verification, shared-number account selection, subscription and saved-card review, confirmed saved-card deletion and subscription card selection, basic account details, confirmed auto-renew changes, optional speech-based profile and delivery-field changes, and an optional saved-card renewal flow. Account changes and renewals are disabled by default. The caller can transfer to the office; new signups, new subscriptions, new-card collection, email verification and other unsupported free-text changes are **not implemented** and require the office. Caller ID is not treated as verification. Calls with more than eight accounts or subscriptions are transferred rather than truncated. No card data is collected.

## Windows deployment

1. Install PHP 8.5 with the cURL extension and configure IIS (or another HTTPS web server) with document root `D:/www/dvapp`. Copy `public/index.php` there. Copy `private/app.php` and `private/.env.example` to `D:/private/dvapp`, and rename the latter to `.env`. Alternatively set `DVAPP_PRIVATE_DIR` in the web server environment to the private directory. Never serve the private directory.
2. Fill in `DV_API_KEY`, a separate long random `WEBRESPONDER_KEY`, the public HTTPS `WEBRESPONDER_URL` ending in `/index.php`, and optionally the dial-plan `OFFICE_DESTINATION` as a fallback. Leave it empty to end safely instead of forwarding when no request destination is provided. Ensure the PHP worker can read the private files and create/write the configured state and log directories; deny other users access. HTTPS and outbound access to the Dee Voch API are required.
3. Point a NetSapiens To-Web dial translation at `https://your-host/index.php?key=YOUR_WEBRESPONDER_KEY&destination=OFFICE_EXTENSION`. The initial request must include `AccountDomain` (from NetSapiens); the office transfer becomes `sip:OFFICE_EXTENSION@AccountDomain`. The destination is saved for the call, not read again on callbacks. Invalid destinations or domains end the call safely. Configure the destination only in trusted PBX routing and restrict access to the endpoint; anyone with the responder key can otherwise select a transfer destination. Configure POST if desired; the endpoint accepts GET or form POST. Route through a system user, as NetSapiens recommends for forwarding. NetSapiens v44.1+ with a working Voice Services TTS integration is required for `<Response>`, `<Say>`, and enhanced `<Gather>`. Test the destination and prompts on your PBX.
4. The Web Responder secret is necessarily present in callback URLs. Configure IIS, proxies, PBX and monitoring to **suppress or redact query strings** and request bodies; restrict access by trusted PBX source IP where possible. Do not expose the Dee Voch API key. OTP digits and session tokens must not be logged or recorded. Disable call recording during verification; the app cannot control PBX recordings.
5. Confirm the test account and one-time codes with Dee Voch. Test incoming calls, timeouts, invalid codes, shared phone numbers, office transfer and auto-renew rules before going live. Set the live base URL only when supplied.

State is stored server-side under random 256-bit IDs, with a 30-minute inactivity limit. Normal exit and transfer close the Dee Voch session; unexpected caller hangups cannot be detected by this implementation, so the API session expires on its own. Abandoned local state files older than 24 hours are opportunistically removed at the start of calls; configure a scheduled cleanup if calls are infrequent. Protect state files as sensitive data. Do not run multiple servers without shared, locking-capable state storage.

`CALLER_ID_DIGIT_STYLE`, `TTS_VOICE`, `TTS_LANGUAGE`, `INPUT_TIMEOUT_SECONDS`, `INTERDIGIT_TIMEOUT_SECONDS`, `MAX_ATTEMPTS`, `LOG_LEVEL` and `LOG_RETENTION_DAYS` are configured in the private `.env`. Logging records safe diagnostics such as HTTP status, numeric cURL error, a fixed operation name and API error code, but never request bodies, URLs, verification codes or session tokens. If LOG_DIR is unset or unwritable, a fixed warning is written to the PHP error log. No message is sent by this application; Dee Voch delivers verification codes. Dev SMS is disabled. Dee Voch reports that dev charges now use the USAePay sandbox; approval and decline test cards are available from Dee Voch.

Renewals require `ENABLE_RENEWALS=true`. Do not enable until end-to-end testing and approval: the PBX and sandbox have not been tested in this environment. A renewal reads the quote, asks about auto-renew, then requires an explicit charge confirmation. A unique idempotency key and uncertain state are saved before the request. If the result is ambiguous, the caller is transferred to the office without an automatic retry; the office must check the order before any further attempt. This does not guarantee recovery after storage failure or across independent deployments.

Account changes require `ENABLE_ACCOUNT_CHANGES=true`. This preliminary flow accepts English speech for name, email, and individual address fields, and keypad input for phone and ZIP. Each change is read back and requires confirmation before submission. Confirm speech transcription accuracy, email formatting, recognition privacy and address validation on the PBX before enabling. Editing a single address component at a time may not work for every cross-zone move; transfer to the office if necessary. Email removal and secondary-phone removal are not supported. Speech transcripts may contain personal data and must be protected at the PBX, voice provider and HTTP infrastructure.

## Open deployment decisions

- Supply the office destination in the To-Web URL and confirm the system-user routing and TTS voice/language.
- Confirm whether caller ID can be withheld or changed: this version transfers rather than accepting an alternate number, and supports SMS only. Landline/email verification transfers to the office.
- The office completes new-customer signup. New subscription orders for existing customers, gifts and promo flows are not implemented. New-card collection remains with the office. Avoid collecting card data or OTPs in recordings, transcripts, and logs; assess PCI obligations before adding payments.
- Confirm how the PBX behaves on a Gather timeout and whether it propagates the action URL query parameters. Callbacks should preserve `key` and `state` and supply `Digits`. Confirm TLS, inbound firewall restrictions, and log redaction end-to-end.

Run `php tests/smoke.php` for basic helper and timeout checks. A real PBX and Dee Voch test account are needed for integration testing.

## Verification troubleshooting

Set `LOG_LEVEL=info` and `LOG_DIR=D:/private/dvapp/logs`, ensure the IIS application pool identity can create and write files there, then make a fresh test call and inspect the UTC-dated log. If there is no file, inspect the PHP/IIS error log for the fixed DVSystem log warning. The API diagnostic identifies `verification_check`, the HTTP status, the numeric cURL error, JSON validity and any safe API error code; do not share request URLs, session identifiers, OTPs or keys. A status of 0 or a nonzero cURL code suggests a connectivity or TLS problem; HTTP 401, 410, 429 or 5xx should be investigated with Dee Voch. A 200/201 still requires a session token and customer array.

Use HTTPS between NetSapiens and the app. The bearer-style Web Responder key and call state are in callback URLs, so rotate a key if its URL has been exposed and prevent query strings from being logged. Include `destination` in the initial To-Web URL if office transfer is desired.

## Call navigation

Interactive prompts announce star to repeat and 9 to go back. Pound is reserved for the PBX send or terminator function. Going back restores the previous prompt without executing its action; confirmation history is cleared after a completed or canceled change or renewal. At the first menu, 9 repeats that menu. Speech prompts also accept DTMF. On multi-digit prompts, NetSapiens may wait for its interdigit timeout before submitting a single navigation key. Test star and 9 on the deployed PBX, including speech and numeric input. A single 9 is treated as back; a complete multi-digit value containing 9 remains data.
